# Website localization foundation

Branch: `feat/multilingual-foundation`.

`src/i18n/locales.mjs` defines English, Japanese, Spanish, German, French, Brazilian Portuguese, and optional European Portuguese. Astro reserves their locale prefixes; existing English root URLs stay unchanged.

`src/i18n/pages.mjs` records reviewed, published equivalents by their English path. It currently contains no translated pages. Only real equivalents may appear in the language switcher and reciprocal alternate-language links. The shared layout sets page language and Open Graph locale and retains a self-canonical. An unpublished localized page fails the build instead of producing misleading metadata.

Before adding a locale to a page's published list:

1. Translate and review the page, shared navigation/footer/consent/accessibility text, screenshots, and linked essential journey using the plugin glossary.
2. Create its locale route, keeping product facts from `src/config.ts` and the released plugin readme.
3. Add the reviewed page to the published-equivalence registry. Use the same page path under each locale prefix; introduce explicit URL mappings if translated slugs are added later.
4. Verify reciprocal links, canonical/language metadata, sitemap inclusion, page-context switching, and honest optional-document fallbacks.
5. Run `npm run test:i18n` and `npm run build`.

The locale registry is infrastructure, not a claim that the translations have shipped. No browser-language redirects or placeholder translated pages are introduced. Locale-aware collections, localized shared website copy, account/email handoffs, and reviewed page translations are the next work packages. There is no separately implemented account service in this repository; inspect the Freemius boundary before claiming full account-language coverage.
