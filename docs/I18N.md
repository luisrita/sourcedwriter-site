# Website localization implementation

Branch: `feat/multilingual-foundation`. English keeps its existing root URLs. The five new editions use `/ja/`, `/es/`, `/de/`, `/fr/`, and `/pt-br/`. European Portuguese is reserved in the locale registry but has no pages or advertised alternates.

## Coverage

Each of the five locales contains 19 pages (95 total): home, features, pricing, FAQ, about/contact, website privacy, changelog overview, documentation index, and 11 essential guides covering installation, providers/keys, jobs/cron, workflows, editor/SEO, sources/citations, writer profiles, cost ceilings, troubleshooting, plugin privacy and Pro. FAQs have all 13 questions. Shared navigation, footer, cookie consent and accessibility labels are translated.

The localized editions are concise, substantive editions of the core journeys. The longer English guides and historical changelog remain linked as explicitly English full versions. Optional blog guides remain English and receive no fabricated language alternates. English screenshots and extended marketing/editorial assets still require a separate localization/editorial pass before claiming complete parity with every English asset.

Content is in `src/content/localized/`, loaded as an Astro collection. Each entry records the English source revision, review status and reviewer. The translations are AI-assisted development copy; all five fluent reviews are pending. They are available in the branch's build and have not been published.

## Behavior

- The URL chooses the language; no browser-language redirects occur. Explicit switcher choices are stored separately in browser local storage.
- Switching preserves equivalent page, query parameters and help anchors. Native language names are used. Optional English-only guides remain clearly labelled.
- Product names, minimum versions, URLs and commercial values use `src/config.ts`. Shared locale formatting keeps EUR currency independent of a visitor's language or country.
- Every equivalent has its own canonical, HTML language, Open Graph locale and reciprocal `hreflang` plus English `x-default`. The sitemap includes the actual translated HTML pages.
- All editions have Markdown twins, `llms.txt` and `llms-full.txt`. No missing page is replaced by a link to an unrelated homepage.
- Plugin errors link to real localized troubleshooting anchors. Privacy and usage-data anchors remain stable.
- Hosted Freemius checkout accepts Spanish, German and French. Japanese and Portuguese use English, preserving product/plan/currency/trial/billing parameters. There are no product-owned signup, account or transactional email templates in this site repository. Freemius owns those surfaces and needs provider review.

Reference: https://v3.freemius.com/help/documentation/checkout/features/local-languages-currencies/

## Verification

```sh
npm run test:i18n
npm run build
npm run test:i18n:build
```

Seven source tests cover locale/security rules, content parity, all help anchors and checkout parameters. Two production tests inspect every real equivalent's HTML metadata/sitemap plus FAQ schema, help targets, Markdown and full indexes. The existing deployment workflow runs both test suites before its deployment job.

On 7 October 2026: 120 HTML pages built; all tests passed. German and Japanese troubleshooting pages were inspected at 375px without horizontal overflow; a language-switch click preserved query and anchor. Consent remains opt-in. These checks do not replace fluent review, comprehensive keyboard/zoom checks or commercial/provider integration validation.

## Updating a language

1. Change source facts in config and English content, then update all affected localized entries and their descriptions/metadata.
2. Record the new English source revision and set affected entries to `needs-review`, with reviewer unset.
3. Have a fluent reviewer assess wording, sources, pricing, privacy, layout and the essential journey. Set `reviewed` and reviewer identity only after that review.
4. Keep the equivalent registry synchronized with real routes; optional English-only pages must not acquire translated alternates.
5. Run both test suites and the production build. Review new screenshot/caption assets and external provider limitations before release.

Publishing is separate from this implementation. No push or deployment was performed.
